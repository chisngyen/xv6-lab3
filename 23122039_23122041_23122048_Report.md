## 3. Chi tiết thực hiện

### 3.1 Large files - Mở rộng kích thước file

#### 3.1.1 Phân tích vấn đề

**Vấn đề ban đầu:** Hệ thống file xv6 giới hạn kích thước file tối đa ở 268 blocks (268 × 1024 bytes). Giới hạn này đến từ cấu trúc inode:
- 12 direct blocks
- 1 singly-indirect block (chứa 256 block addresses)
- Tổng: 12 + 256 = **268 blocks**

**Mục tiêu:** Tăng kích thước file tối đa lên **65803 blocks** bằng cách thêm doubly-indirect block.

**Công thức tính:**
```
11 direct blocks                           =     11 blocks
1 singly-indirect block (256 entries)      =    256 blocks  
1 doubly-indirect block (256 × 256)        = 65,536 blocks
─────────────────────────────────────────────────────────
Tổng cộng                                  = 65,803 blocks
```

#### 3.1.2 Cài đặt chi tiết

**1. Cập nhật cấu trúc dữ liệu:**

*File: `kernel/fs.h`*
```c
#define NDIRECT 11                                        // Giảm từ 12 xuống 11
#define NINDIRECT (BSIZE / sizeof(uint))                  // = 256
#define MAXFILE (NDIRECT + NINDIRECT + NINDIRECT * NINDIRECT)  // = 65803

struct dinode {
  // ...
  uint addrs[NDIRECT+2];   // Tăng từ NDIRECT+1 lên NDIRECT+2
};
```

*File: `kernel/file.h`*
```c
struct inode {
  // ...
  uint addrs[NDIRECT+2];   // Đồng bộ với struct dinode
};
```

**2. Mở rộng hàm `bmap()` trong `kernel/fs.c`:**

Nhóm đã thiết kế lại hàm `bmap()` với cấu trúc rõ ràng, sử dụng các biến có tên ý nghĩa:

```c
// Xử lý doubly-indirect blocks
if(bn < NINDIRECT * NINDIRECT){
    // Tính toán chỉ số 2 cấp
    uint outer_idx = bn / NINDIRECT;  // Chỉ số trong doubly-indirect block
    uint inner_idx = bn % NINDIRECT;  // Chỉ số trong singly-indirect block
    
    // Bước 1: Load doubly-indirect block
    // Bước 2: Lấy địa chỉ singly-indirect block tại vị trí outer_idx
    // Bước 3: Load singly-indirect block và lấy địa chỉ data block
    // ...
}
```

**Điểm khác biệt trong thiết kế:**
- Sử dụng tên biến `outer_idx`, `inner_idx` thay vì `idx1`, `idx2` để rõ nghĩa hơn
- Tách riêng buffer cho từng level: `dbl_buf`, `sgl_buf` thay vì tái sử dụng cùng biến
- Thêm comments tiếng Việt giải thích từng bước

**3. Cập nhật hàm `itrunc()` trong `kernel/fs.c`:**

Thêm logic giải phóng doubly-indirect blocks với cấu trúc 3 bước:
- Bước 1: Giải phóng tất cả direct blocks
- Bước 2: Giải phóng singly-indirect block và các data blocks bên trong
- Bước 3: Giải phóng doubly-indirect block và tất cả blocks bên trong

```c
// Bước 3: Giải phóng doubly-indirect block
if(ip->addrs[NDIRECT+1]){
    struct buf *dbl_buf = bread(ip->dev, ip->addrs[NDIRECT+1]);
    uint *dbl_addrs = (uint*)dbl_buf->data;
    
    for(int outer_idx = 0; outer_idx < NINDIRECT; outer_idx++){
        if(dbl_addrs[outer_idx]){
            // Đọc và giải phóng từng singly-indirect block
            struct buf *sgl_buf = bread(ip->dev, dbl_addrs[outer_idx]);
            uint *sgl_addrs = (uint*)sgl_buf->data;
            
            for(int inner_idx = 0; inner_idx < NINDIRECT; inner_idx++){
                if(sgl_addrs[inner_idx])
                    bfree(ip->dev, sgl_addrs[inner_idx]);
            }
            brelse(sgl_buf);
            bfree(ip->dev, dbl_addrs[outer_idx]);
        }
    }
    brelse(dbl_buf);
    bfree(ip->dev, ip->addrs[NDIRECT+1]);
    ip->addrs[NDIRECT+1] = 0;
}
```

### 3.2 Symbolic links - Liên kết mềm

#### 3.2.1 Phân tích yêu cầu

**Mục tiêu:** Cài đặt symbolic links (soft links) cho phép tạo liên kết đến file thông qua đường dẫn.

**Khác biệt với hard links:**
- Hard links: chỉ trỏ đến file trên cùng device, tăng nlink count
- Symbolic links: có thể trỏ đến file trên device khác, lưu đường dẫn trong data blocks

**Chức năng cần thực hiện:**
1. System call `symlink(target, path)` để tạo symbolic link
2. Modify `open()` để tự động follow symbolic links
3. Flag `O_NOFOLLOW` để mở chính symlink thay vì follow nó
4. Phát hiện và ngăn chặn vòng lặp vô hạn (max depth = 10)

#### 3.2.2 Cài đặt chi tiết

**1. Định nghĩa constants và types mới:**

*File: `kernel/stat.h`*
```c
#define T_SYMLINK 4   // Loại file symbolic link
```

*File: `kernel/fcntl.h`*
```c
#define O_NOFOLLOW 0x800  // Flag không follow symlink khi open
```

**2. Đăng ký system call mới:**

*File: `kernel/syscall.h`*
```c
#define SYS_symlink 22
```

*File: `kernel/syscall.c`*
```c
extern uint64 sys_symlink(void);
// ...
[SYS_symlink] sys_symlink,
```

*File: `user/usys.pl`*
```perl
entry("symlink");
```

*File: `user/user.h`*
```c
int symlink(const char*, const char*);
```

**3. Cài đặt `sys_symlink()` trong `kernel/sysfile.c`:**

```c
// Tạo symbolic link (liên kết mềm) từ path trỏ đến target
uint64
sys_symlink(void)
{
  char target[MAXPATH], path[MAXPATH];
  struct inode *ip;

  if(argstr(0, target, MAXPATH) < 0 || argstr(1, path, MAXPATH) < 0)
    return -1;

  begin_op();
  
  // Tạo inode mới với type T_SYMLINK
  ip = create(path, T_SYMLINK, 0, 0);
  if(ip == 0){
    end_op();
    return -1;
  }

  // Sử dụng strlen() thay vì viết for loop thủ công
  int target_len = strlen(target) + 1;  // +1 cho ký tự null
  
  // Ghi đường dẫn target vào data blocks
  if(writei(ip, 0, (uint64)target, 0, target_len) != target_len){
    iunlockput(ip);
    end_op();
    return -1;
  }

  iunlockput(ip);
  end_op();
  return 0;
}
```

**Điểm khác biệt:** Sử dụng `strlen()` có sẵn thay vì viết for loop thủ công để tính độ dài.

**4. Modify `sys_open()` để follow symlinks:**

```c
// Giới hạn độ sâu để phát hiện vòng lặp (cycle)
#define SYMLINK_MAX_DEPTH 10

// Trong sys_open():
if(ip->type == T_SYMLINK && !(omode & O_NOFOLLOW)){
    char symlink_target[MAXPATH];
    
    // Dùng for loop với đếm số lần follow
    for(int follow_count = 0; follow_count < SYMLINK_MAX_DEPTH; follow_count++){
        if(ip->type != T_SYMLINK)
            break;
            
        int bytes_read = readi(ip, 0, (uint64)symlink_target, 0, MAXPATH - 1);
        if(bytes_read <= 0){
            iunlockput(ip);
            end_op();
            return -1;
        }
        symlink_target[bytes_read] = '\0';
        iunlockput(ip);
        
        ip = namei(symlink_target);
        if(ip == 0){
            end_op();
            return -1;
        }
        ilock(ip);
    }
    
    // Nếu vẫn là symlink sau SYMLINK_MAX_DEPTH lần -> có vòng lặp
    if(ip->type == T_SYMLINK){
        iunlockput(ip);
        end_op();
        return -1;
    }
}
```

**Điểm khác biệt:**
- Định nghĩa constant `SYMLINK_MAX_DEPTH` thay vì dùng magic number 10
- Sử dụng for loop với biến `follow_count` thay vì while loop với `depth`
- Đặt tên biến `symlink_target` rõ nghĩa hơn
- Check cycle sau vòng lặp thay vì check `depth >= 10`
